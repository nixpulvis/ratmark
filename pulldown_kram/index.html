A kramdown parser built on pulldown-cmark.

kramdown is a Markdown dialect (like GFM) which Jekyll uses by default, and supports many extensions which are listed below. This crate parses it into pulldown_cmark::Events, pairing each event with the Attributes that kramdown attribute lists such as {: .note #intro} assign to it.

use pulldown_kram::{Document, Extensions, pulldown_cmark::{Event, Tag}};

let document = Document::new("# Intro\n\nSee `x`{:.new}.\n", Extensions::all());
let events: Vec<_> = document.events().collect();

// `# Intro` gets the id `intro`, as in kramdown.
assert!(matches!(
    &events[0].0,
    Event::Start(Tag::Heading { id: Some(id), .. }) if id.as_ref() == "intro"
));

// `{:.new}` gives the code span before it the class `new`.
let (_, attributes) = events
    .iter()
    .find(|(event, _)| matches!(event, Event::Code(_)))
    .unwrap();
assert!(attributes.has_class("new"));

html::push_html renders the events as HTML the way kramdown does, attributes included. The html module mirrors pulldown_cmark::html.

§Syntax support

What’s supported from kramdown’s syntax, following the sections of its documentation. An item marked ☑ works as it does in kramdown. One marked ⊟ does apart from the ☐ items after it. One marked ☐ doesn’t, and says what happens instead. Items that need one of the Extensions start with its name. Each extension can be turned off on its own, and Extensions::all() turns them all on.

§Source text

  • ⊟ Tab stops every four columns.
  • ☐ A tab after a blockquote marker counting toward a code block’s indent, so > \tcode is a code block. Instead, it’s a paragraph.
  • ☐ Headers only on a block boundary. kramdown’s GFM parser lets an atx header interrupt a paragraph, as here, but a setext underline after a paragraph of two or more lines stays text. Instead, the paragraph’s lines become the header.
  • ☐ Lazy lines that start a block, like > a\n# b, kept in the blockquote or list item, as kramdown’s GFM parser keeps them. Instead, the blockquote or list item ends.
  • ⊟ ENABLE_KRAMDOWN_ESCAPES: Backslash escapes, for exactly the characters kramdown escapes. A backslash before any other character is kept.
  • ☐ ENABLE_KRAMDOWN_ESCAPES: Backslashes in link URLs and titles, which kramdown keeps. Instead, they escape there too.

§Structural elements

  • ☑ Hard line breaks with two trailing spaces.
  • ⊟ Paragraphs, including lazy continuation lines.
  • ☐ A paragraph that a horizontal rule doesn’t interrupt, so para\n*** stays one paragraph. Instead, the rule ends it.
  • ☐ An ordered list interrupting a paragraph whatever its first number, like para\n2. two. Instead, it’s text.
  • ⊟ Setext and atx headers, including the header\n--- edge case.
  • ☐ Headers only in the first column, so # a, or an underline indented by a space, stays text. Instead, they make headers.
  • ☐ Empty atx headers, like #, kept as text. Instead, they’re empty headings.
  • ⊟ Blockquotes, including nested and lazy ones.
  • ⊟ Indented code blocks, continuing across blank lines.
  • ☐ Lazy continuation lines in an indented code block. Instead, they end the code block and start a paragraph.
  • ⊟ Fenced code blocks with ~~~, with an optional language after the fence.
  • ☐ Words after a fence’s language making the lines a paragraph. Instead, they’re a code block.
  • ☐ An unclosed fence read as a paragraph. Instead, the code block runs to the end of the document.
  • ☐ A fence indented by one to three spaces keeping that indent on its lines. Instead, it’s stripped.
  • ⊟ Ordered and unordered lists, nested or compact, and 1984\. to escape a list marker.
  • ☐ A list item with nothing on its first line and a code block after it. Instead, the code keeps two more spaces of indent.
  • ☐ A list item’s text starting wherever it starts after the marker, so * text is text. Instead, five or more spaces start a code block, as in CommonMark.
  • ☐ 1) read as text. Instead, it’s an ordered list marker.
  • ☐ An ordered item right after an unordered one nested in it. Instead, it starts a new list.
  • ☐ An unindented fenced code block on the line right after a list item’s text, which kramdown keeps in the item as a lazy line, with the item’s indent removed from its lines. Instead, it ends the list.
  • ☐ Keeping the extra indent of a fenced code block indented past a list item’s content. Instead, the indent is stripped from its lines.
  • ☐ Ordered lists always numbered from 1. Instead, the first number is kept.
  • ⊟ Horizontal rules.
  • ☐ * * * right after a list item read as a nested item. Instead, it’s a rule.
  • ☐ HTML rewritten as kramdown writes it: tag and attribute names lowercased, unclosed tags closed, and stray end tags made text. Instead, it’s passed through as pulldown-cmark HTML events, for the program reading them to handle.
  • ☐ The parse_block_html option. Instead, HTML blocks are read as with it off, kramdown’s default.
  • ☐ Any tag that isn’t span-level starting an HTML block, even on a paragraph’s next line. Instead, an unknown tag stays in the paragraph.
  • ☐ Processing instructions and CDATA sections written as kramdown writes them. Instead, they’re kept as HTML.
  • ☐ XML-namespaced tags, like <x:y>, read as HTML. Instead, they’re text.
  • ☑ ENABLE_BACKSLASH_LINE_BREAKS: Hard line breaks with two trailing backslashes.
  • ☑ ENABLE_LANGUAGE_CLASSES: A code block’s language from an attribute list, {: .language-ruby}, when the fence doesn’t give one.
  • ☑ ENABLE_MIXED_LIST_MARKERS: Mixing *, + and - in one list.
  • ⊟ ENABLE_HEADER_IDS: Header ids, # Hello {#id}. As in kramdown, # Hello {: #id} is left as text.
  • ☐ ENABLE_HEADER_IDS: Every id kramdown accepts, any XML name like {#a.b} or {#_x}. Instead, those are left as text.
  • ☐ ENABLE_HEADER_IDS: An id before an atx header’s closing hashes, # A {#a} ##, left as text. Instead, it’s the header’s id.
  • ⊟ ENABLE_LIST_ITEM_PARAGRAPHS: Tight and loose list items decided per item, not per list: an item’s first paragraph isn’t wrapped in a paragraph unless a blank line follows it.
  • ☐ ENABLE_LIST_ITEM_PARAGRAPHS: An end-of-block marker after a list wrapping its last item in a paragraph. Instead, the item stays tight.
  • ⊟ ENABLE_TASK_LISTS: Task list items, * [x] done, from kramdown’s GFM parser.
  • ☐ ENABLE_TASK_LISTS: Task items as kramdown’s GFM parser reads them: an empty [ ] is text, and * {:.c} [x] a is a task. Instead, the empty box is a task, and the box after an attribute list is text.
  • ⊟ ENABLE_DEFINITION_LISTS: Definition lists, one term per line. A definition’s first paragraph isn’t wrapped in a paragraph unless a blank line comes before it. At most one blank line may separate the terms from their first definition, any number may separate definitions, and a definition with an empty first line is indented by four spaces.
  • ☐ ENABLE_DEFINITION_LISTS: Separate terms on lines joined by one span, like *a\nb*. Instead, they form a single term.
  • ☐ ENABLE_DEFINITION_LISTS: A definition’s first line with its leading whitespace stripped, so : text is a paragraph. Instead, four or more spaces make it code.
  • ☐ ENABLE_DEFINITION_LISTS: A space or tab required after the :. Instead, term\n:text is a definition list.
  • ⊟ ENABLE_TABLES: Tables with a header row.
  • ☐ ENABLE_TABLES: Several header rows above the separator line. Instead, the rows before the last make a paragraph.
  • ☐ ENABLE_TABLES: Rows wider than the header, widening the table. Instead, the extra cells are dropped.
  • ☐ ENABLE_TABLES: A table with a header followed by a line that isn’t a row, which makes it all a paragraph. Instead, it’s a table, with the line as another row.
  • ☐ ENABLE_TABLES: A header and separator line with no rows after them read as a paragraph. Instead, they’re a table.
  • ☐ ENABLE_TABLES: Separator lines in a table body, and footer separator lines, |===. Instead, each is a row of dashes or equals signs after a header row. Without one, |=== is a header’s separator line, and a table with a separator after its first rows is a paragraph.
  • ☐ ENABLE_TABLES: Two or more lines of only table separators, which kramdown doesn’t treat as a table. Instead, they’re parsed as one.
  • ☑ ENABLE_TABLES_WITHOUT_HEADERS: A separator line with fewer cells than the header, or + between its cells.
  • ⊟ ENABLE_TABLES_WITHOUT_HEADERS: Tables without a header row.
  • ⊟ ENABLE_TABLES_WITHOUT_HEADERS: A | in a code span in a table cell, kept in that cell.
  • ☐ ENABLE_TABLES_WITHOUT_HEADERS: A row starting with | after one that doesn’t, given an empty first cell. Instead, its cells don’t shift.
  • ☐ ENABLE_TABLES_WITHOUT_HEADERS: Tables without a header row in blockquotes, list items and footnotes. Instead, they’re text, with an empty table before them.
  • ☐ ENABLE_TABLES_WITHOUT_HEADERS: A \| in a code span in a table cell keeping its backslash. Instead, it’s dropped.
  • ☐ ENABLE_TABLES_WITHOUT_HEADERS: A | in HTML <code> in a cell kept in that cell. Instead, it starts another cell.
  • ☐ ENABLE_TABLES_WITHOUT_HEADERS: A code span over two lines of a table, which makes them a paragraph. Instead, they’re a table.
  • ☐ ENABLE_TABLES_WITHOUT_HEADERS: A line with a | only inside inline math read as a table row. Instead, it’s a paragraph.
  • ⊟ ENABLE_MATH: Math blocks, $$…$$ alone in a paragraph.
  • ☐ ENABLE_MATH: Blank lines in a math block. Instead, a blank line splits it into paragraphs.
  • ☐ ENABLE_MATH: Math blocks only between block boundaries, so $$ right after or right before a fence or header is inline math in a paragraph. Instead, it’s a math block.
  • ☐ ENABLE_MATH: $$…$$ alone in a list item or definition read as a math block. Instead, it’s inline math.
  • ⊟ ENABLE_HTML_BLOCK_ENDS: HTML blocks, with Markdown inside them left as HTML. A block ends at the end tag of the element that opened it, and text after that is parsed as Markdown, as long as no blank line comes before the end tag.
  • ☐ ENABLE_HTML_BLOCK_ENDS: Blank lines inside an HTML block. Instead, as in CommonMark, a blank line ends the block, and what follows is parsed as Markdown.
  • ☐ ENABLE_HTML_BLOCK_ENDS: Every element that isn’t span-level, like <details> or a custom tag, ending at its end tag. Instead, an element outside a fixed list runs to the next blank line.
  • ☐ ENABLE_HTML_BLOCK_ENDS: An end tag inside a comment or an attribute value leaving the block open. Instead, it ends the block early.
  • ☐ ENABLE_HTML_BLOCK_ENDS: HTML blocks in a blockquote ending at their end tag. Instead, they run to the next blank line.
  • ⊟ ENABLE_MARKDOWN_ATTRIBUTE: markdown="1" on a block element. Its content is parsed as Markdown and the attribute is removed.
  • ☐ ENABLE_MARKDOWN_ATTRIBUTE: markdown="1" on elements whose content kramdown reads as spans, like <p> and <h1>. Instead, their content is left as HTML.
  • ☐ ENABLE_MARKDOWN_ATTRIBUTE: markdown="1" with text on the start tag’s line, or after the end tag. Instead, that text is left as HTML.
  • ☐ ENABLE_MARKDOWN_ATTRIBUTE: markdown='1', in single quotes. Instead, it’s ignored.
  • ☐ ENABLE_MARKDOWN_ATTRIBUTE: markdown="block", markdown="span" and markdown="0". Instead, the attribute is kept, and the content is left as HTML in a block element and parsed as Markdown in a span.
  • ⊟ ENABLE_SPAN_TAG_PARAGRAPHS: A line with only a span-level tag, like <img>, starting a paragraph together with the text on the next line.
  • ☐ ENABLE_SPAN_TAG_PARAGRAPHS: A line with only a span-level tag, followed by a blank line, as a paragraph of its own. Instead, it’s an HTML block.
  • ☐ ENABLE_SPAN_TAG_PARAGRAPHS: Lines in <pre> left as written. Instead, a line with only a span-level tag is joined to the next there too.

§Text markup

  • ⊟ Automatic links, <http://example.com> and <me@example.com>.
  • ☐ <mailto:me@example.com> with only the address as the link text. Instead, the link text includes mailto:.
  • ☐ Automatic links with a space in the URL, or a non-ASCII email address. Instead, they’re text.
  • ⊟ Inline links, with single- or double-quoted titles.
  • ☐ Inline link titles as kramdown reads them: an empty title leaves the whole link as text, and a title in parentheses is part of the URL. Instead, the first is a link without a title, and the second a title.
  • ☐ Spaces in an inline link’s URL, [a](b c.html). Instead, it’s parsed as text.
  • ☐ A link inside link text, [a [b](v) c](u), left as text in the outer link. Instead, the inner one is the link.
  • ⊟ Reference links, [text][id], [text][] and [text], matched case-insensitively.
  • ☐ Spaces or a line break between a reference link’s brackets, [text]\n[id]. Instead, each pair of brackets is read on its own.
  • ☐ Brackets in a reference link’s text, [[1]][1]. Instead, the inner brackets form the link and the outer ones are text.
  • ⊟ Link definitions, and \: to keep one as text.
  • ☐ The last link definition of a name winning. Instead, the first wins.
  • ☐ Link definitions with a space in the URL, [a]: b c, or a title in parentheses, which kramdown takes as part of the URL. Instead, the first is text and the second a title.
  • ⊟ Images, inline and by reference.
  • ☐ An image’s alt text as written, including markup and straight quotes, with only backslash escapes applied. Instead, its markup is parsed and its dashes, ellipses and quotes made typographic.
  • ⊟ Emphasis and strong emphasis. * works inside words, _ doesn’t.
  • ☐ Emphasis delimiter runs kramdown reads differently, like a*"b"*c or This is **a *star*. Instead, they’re read by CommonMark’s rules.
  • ☐ Empty emphasis, ****, written as <em>**</em>. Instead, it’s text.
  • ☐ Emphasis inside the same kind of emphasis, *a _b_ c* or _*b*_, left literal. Instead, it nests.
  • ☐ ***a*** and ___a___ as strong emphasis around emphasis. Instead, they’re emphasis around strong emphasis.
  • ⊟ Code spans.
  • ☐ A backtick next to a space kept literal, as in ` a `. Instead, it opens a code span.
  • ⊟ HTML spans, with Markdown parsed inside them.
  • ☐ The HTML spans kramdown leaves raw beyond its documented ones, like <u>, <mark> and custom elements. Instead, Markdown is parsed in them.
  • ☐ Unclosed HTML spans closed, and stray end tags and block tags in a paragraph made text. Instead, they’re kept as HTML.
  • ☐ The parse_span_html option. Instead, HTML spans are read as with it on, kramdown’s default.
  • ☐ Guillemets from << and >>. Instead, they’re parsed as text or as an HTML tag.
  • ☑ ENABLE_ABBREVIATIONS: Abbreviations, *[HTML]: …. Each use becomes an <abbr> in HTML events, with the attributes of any attribute lists on the lines around the definition.
  • ⊟ ENABLE_FOOTNOTES: Footnotes, with block content in their definitions.
  • ☐ ENABLE_FOOTNOTES: The last footnote definition of a name winning, and a lazy line ending a definition. Instead, the first wins, and lazy lines continue it.
  • ☐ ENABLE_FOOTNOTES: A footnote definition on a paragraph’s next line kept as text. Instead, it’s a footnote.
  • ☐ ENABLE_FOOTNOTES: A table or math block indented in a footnote definition. Instead, it’s text.
  • ⊟ ENABLE_TYPOGRAPHY: Dashes, ellipses and smart quotes.
  • ☐ ENABLE_TYPOGRAPHY: Smart quotes where kramdown curls them the other way, like 'Tis and 5'10". Instead, they’re curled as pulldown-cmark curls them.
  • ☐ ENABLE_TYPOGRAPHY: Runs of four or more dashes made into dashes as kramdown makes them. Instead, they’re en dashes.
  • ⊟ ENABLE_MATH: Inline math, $$…$$ in a paragraph with other content. $…$ stays text.
  • ☐ ENABLE_MATH: \$$…$$ to make math alone in a paragraph inline. Instead, it’s left literal.
  • ⊟ ENABLE_STRIKETHROUGH: Strikethrough, ~~…~~, from kramdown’s GFM parser. ~…~ stays text.
  • ☐ ENABLE_STRIKETHROUGH: Runs of tildes kramdown’s GFM parser reads differently, like ~~a~~~, and ~~~a~~~ as a paragraph. Instead, the first is text and the second a fence.
  • ⊟ ENABLE_RAW_HTML_SPANS: The HTML spans kramdown leaves raw, like <kbd> and <code>, their text passed through unchanged.
  • ☐ ENABLE_RAW_HTML_SPANS: A nested tag of the same name in a raw HTML span, like <kbd>a <kbd>b</kbd> c</kbd>. Instead, the first end tag ends the raw text.

§Non-content elements

  • ☑ Tags for extensions kramdown doesn’t have, like {::something}, left as text.
  • ☐ Definition attribute lists, : {:.cls} definition. Instead, they’re parsed as text.
  • ☐ Term attribute lists, {:#id} term. Instead, they’re parsed as text.
  • ☐ Attribute list definitions, {:name: .class}, and references to them, including kramdown’s standalone, footnotes and auto_ids. Instead, definitions are removed and references ignored.
  • ☐ The options extension. Instead, its block form is removed, with any body kept as Markdown, and its span form is left as text.
  • ⊟ ENABLE_END_OF_BLOCK_MARKERS: The end-of-block marker ^, closing the paragraph, list, blockquote or code block before it.
  • ☐ ENABLE_END_OF_BLOCK_MARKERS: An indented ^ kept as text. Instead, it’s a marker.
  • ☐ ENABLE_END_OF_BLOCK_MARKERS: A marker after an HTML block. Instead, it’s text.
  • ⊟ ENABLE_BLOCK_ATTRIBUTES: Block attribute lists, on the line before or after a block, or alone between blocks to apply to the next one.
  • ⊟ ENABLE_BLOCK_ATTRIBUTES: Block attribute lists on link definitions, applied to the links and images that use them.
  • ☐ ENABLE_BLOCK_ATTRIBUTES: A block attribute list after a list item ending the list. Instead, it’s applied to the list, but the items after it stay in the same list.
  • ☐ ENABLE_BLOCK_ATTRIBUTES: Block attribute lists on HTML blocks. Instead, one before the block is dropped, and one after goes to the next block.
  • ☐ ENABLE_BLOCK_ATTRIBUTES: An attribute list indented by four spaces kept as text. Instead, it’s read.
  • ☐ ENABLE_BLOCK_ATTRIBUTES: An attribute list’s attribute replacing the element’s own of the same name, like an ordered list’s start. Instead, both are written.
  • ⊟ ENABLE_SPAN_ATTRIBUTES: Span attribute lists, directly after emphasis, a link, an image or a code span.
  • ⊟ ENABLE_SPAN_ATTRIBUTES: The empty span attribute list, {::}, as a separator between spans.
  • ☐ ENABLE_SPAN_ATTRIBUTES: Span attribute lists after a collapsed reference link, [a][]{:.c}. Instead, they’re text.
  • ☐ ENABLE_SPAN_ATTRIBUTES: Span attribute lists after HTML spans and inline math. Instead, they’re text.
  • ☐ ENABLE_SPAN_ATTRIBUTES: {::} on a line of its own kept as text. Instead, it’s dropped.
  • ⊟ ENABLE_ITEM_ATTRIBUTES: List item attribute lists, * {:.cls} item.
  • ☐ ENABLE_ITEM_ATTRIBUTES: Only the first of two item attribute lists read, * {:.a}{:.b} item. Instead, both are.
  • ⊟ ENABLE_COMMENTS: The comment extension, as a block or span, emitted as an HTML comment.
  • ☐ ENABLE_COMMENTS: The comment extension in a blockquote. Instead, it’s text.
  • ⊟ ENABLE_NOMARKDOWN: The nomarkdown extension, as a block or span, emitted as raw HTML unless its type names another converter.
  • ☐ ENABLE_NOMARKDOWN: The nomarkdown extension in a blockquote. Instead, it’s text.

§Converter

Not part of the syntax, but features Jekyll sites rely on.

  • ☐ The toc_levels option. Instead, every heading level is listed.
  • ⊟ ENABLE_AUTO_IDS: Automatic header ids, generated from the heading’s text without markup, the same way as kramdown’s GFM parser, Jekyll’s default.
  • ☐ ENABLE_AUTO_IDS: Ids for headings with images or raw HTML spans, made from the spans’ text and not an image’s alt text. Instead, they’re made from the alt text and not the spans’ text.
  • ⊟ ENABLE_TABLES_OF_CONTENTS: {:toc} tables of contents, nested by heading level. Headings with the class no_toc are excluded, and links inside headings are left out. If there are no headings, the marked list is removed.
  • ☐ ENABLE_TABLES_OF_CONTENTS: Only the first list marked {:toc} made a table of contents. Instead, every one is.
  • ☐ ENABLE_TABLES_OF_CONTENTS: kramdown’s ids on a table of contents, markdown-toc on the list and markdown-toc-… on its links. Instead, there are none.

§How it works

Reading a document takes four steps.

  1. The Markdown is rewritten wherever kramdown reads a line differently from CommonMark, so that pulldown-cmark reads it kramdown’s way. For example, a blank line goes in after the end tag of an HTML block, since kramdown ends the block there and CommonMark doesn’t. Syntax pulldown-cmark can’t read at all, like {::comment} or the end-of-block marker, is replaced with a stand-in: a little HTML that pulldown-cmark reads as a block or a span, and that the reader later swaps for what it stands for.
  2. pulldown-cmark parses the rewritten text.
  3. A reader takes the events a block at a time. It takes attribute lists out of the text and attaches them to the elements they belong to, puts back what the stand-ins stand for, and corrects the events where kramdown’s structure differs, like in definition lists, list item paragraphs, header ids and abbreviations.
  4. With tables of contents on, all of the events are read first, and each list marked {:toc} is replaced with links to the headings.

The ranges from Events::into_offset_iter are mapped back through the rewrites, so they point into the Markdown as it was given.
