1//! A [kramdown] parser built on [pulldown-cmark].
2//!
3//! kramdown is a Markdown dialect (like GFM) which [Jekyll] uses by default,
4//! and supports many extensions which are [listed below](#syntax-support).
5//! This crate parses it into [`pulldown_cmark::Event`]s, pairing each event
6//! with the [`Attributes`] that kramdown attribute lists such as
7//! `{: .note #intro}` assign to it.
8//!
9//! ```
10//! use pulldown_kram::{Document, Extensions, pulldown_cmark::{Event, Tag}};
11//!
12//! let document = Document::new("# Intro\n\nSee `x`{:.new}.\n", Extensions::all());
13//! let events: Vec<_> = document.events().collect();
14//!
15//! // `# Intro` gets the id `intro`, as in kramdown.
16//! assert!(matches!(
17//!     &events[0].0,
18//!     Event::Start(Tag::Heading { id: Some(id), .. }) if id.as_ref() == "intro"
19//! ));
20//!
21//! // `{:.new}` gives the code span before it the class `new`.
22//! let (_, attributes) = events
23//!     .iter()
24//!     .find(|(event, _)| matches!(event, Event::Code(_)))
25//!     .unwrap();
26//! assert!(attributes.has_class("new"));
27//! ```
28//!
29//! [`html::push_html`] renders the events as HTML the way kramdown does,
30//! attributes included. The [`html`] module mirrors
31//! [`pulldown_cmark::html`][cmark-html].
32//!
33//! [kramdown]: https://kramdown.gettalong.org
34//! [cmark-html]: https://docs.rs/pulldown-cmark/0.13/pulldown_cmark/html/index.html
35//! [Jekyll]: https://jekyllrb.com
36//! [pulldown-cmark]: https://docs.rs/pulldown-cmark
37//!
38//! # Syntax support
39//!
40//! What's supported from [kramdown's syntax], following the sections of its
41//! documentation. An item marked ☑ works as it does in kramdown. One marked
42//! ⊟ does apart from the ☐ items after it. One marked ☐ doesn't, and says
43//! what happens instead. Items that need one of the [`Extensions`] start
44//! with its name. Each extension can be turned off on its own, and
45//! [`Extensions::all()`] turns them all on.
46//!
47//! [kramdown's syntax]: https://kramdown.gettalong.org/syntax.html
48//!
49//! ## Source text
50//!
51//! - ⊟ Tab stops every four columns.
52//! - ☐ A tab after a blockquote marker counting toward a code block's
53//!   indent, so `> \tcode` is a code block. Instead, it's a paragraph.
54//! - ☐ Headers only on a block boundary. kramdown's GFM parser lets an atx
55//!   header interrupt a paragraph, as here, but a setext underline after a
56//!   paragraph of two or more lines stays text. Instead, the paragraph's
57//!   lines become the header.
58//! - ☐ Lazy lines that start a block, like `> a\n# b`, kept in the
59//!   blockquote or list item, as kramdown's GFM parser keeps them. Instead,
60//!   the blockquote or list item ends.
61//! - ⊟ [`ENABLE_KRAMDOWN_ESCAPES`]: Backslash escapes, for exactly the
62//!   characters kramdown escapes. A backslash before any other character is
63//!   kept.
64//! - ☐ [`ENABLE_KRAMDOWN_ESCAPES`]: Backslashes in link URLs and titles,
65//!   which kramdown keeps. Instead, they escape there too.
66//!
67//! ## Structural elements
68//!
69//! - ☑ Hard line breaks with two trailing spaces.
70//! - ⊟ Paragraphs, including lazy continuation lines.
71//! - ☐ A paragraph that a horizontal rule doesn't interrupt, so
72//!   `para\n***` stays one paragraph. Instead, the rule ends it.
73//! - ☐ An ordered list interrupting a paragraph whatever its first number,
74//!   like `para\n2. two`. Instead, it's text.
75//! - ⊟ Setext and atx headers, including the `header\n---` edge case.
76//! - ☐ Headers only in the first column, so ` # a`, or an underline
77//!   indented by a space, stays text. Instead, they make headers.
78//! - ☐ Empty atx headers, like `#`, kept as text. Instead, they're empty
79//!   headings.
80//! - ⊟ Blockquotes, including nested and lazy ones.
81//! - ⊟ Indented code blocks, continuing across blank lines.
82//! - ☐ Lazy continuation lines in an indented code block. Instead, they
83//!   end the code block and start a paragraph.
84//! - ⊟ Fenced code blocks with `~~~`, with an optional language after the
85//!   fence.
86//! - ☐ Words after a fence's language making the lines a paragraph.
87//!   Instead, they're a code block.
88//! - ☐ An unclosed fence read as a paragraph. Instead, the code block runs
89//!   to the end of the document.
90//! - ☐ A fence indented by one to three spaces keeping that indent on its
91//!   lines. Instead, it's stripped.
92//! - ⊟ Ordered and unordered lists, nested or compact, and `1984\.` to
93//!   escape a list marker.
94//! - ☐ A list item with nothing on its first line and a code block after
95//!   it. Instead, the code keeps two more spaces of indent.
96//! - ☐ A list item's text starting wherever it starts after the marker, so
97//!   `*       text` is text. Instead, five or more spaces start a code
98//!   block, as in CommonMark.
99//! - ☐ `1)` read as text. Instead, it's an ordered list marker.
100//! - ☐ An ordered item right after an unordered one nested in it.
101//!   Instead, it starts a new list.
102//! - ☐ An unindented fenced code block on the line right after a list
103//!   item's text, which kramdown keeps in the item as a lazy line, with the
104//!   item's indent removed from its lines. Instead, it ends the list.
105//! - ☐ Keeping the extra indent of a fenced code block indented past a
106//!   list item's content. Instead, the indent is stripped from its lines.
107//! - ☐ Ordered lists always numbered from 1. Instead, the first number is
108//!   kept.
109//! - ⊟ Horizontal rules.
110//! - ☐ `* * *` right after a list item read as a nested item. Instead,
111//!   it's a rule.
112//! - ☐ HTML rewritten as kramdown writes it: tag and attribute names
113//!   lowercased, unclosed tags closed, and stray end tags made text.
114//!   Instead, it's passed through as pulldown-cmark HTML events, for the
115//!   program reading them to handle.
116//! - ☐ The `parse_block_html` option. Instead, HTML blocks are read as
117//!   with it off, kramdown's default.
118//! - ☐ Any tag that isn't span-level starting an HTML block, even on a
119//!   paragraph's next line. Instead, an unknown tag stays in the paragraph.
120//! - ☐ Processing instructions and CDATA sections written as kramdown
121//!   writes them. Instead, they're kept as HTML.
122//! - ☐ XML-namespaced tags, like `<x:y>`, read as HTML. Instead, they're
123//!   text.
124//! - ☑ [`ENABLE_BACKSLASH_LINE_BREAKS`]: Hard line breaks with two
125//!   trailing backslashes.
126//! - ☑ [`ENABLE_LANGUAGE_CLASSES`]: A code block's language from an
127//!   attribute list, `{: .language-ruby}`, when the fence doesn't give one.
128//! - ☑ [`ENABLE_MIXED_LIST_MARKERS`]: Mixing `*`, `+` and `-` in one list.
129//! - ⊟ [`ENABLE_HEADER_IDS`]: Header ids, `# Hello {#id}`. As in kramdown,
130//!   `# Hello {: #id}` is left as text.
131//! - ☐ [`ENABLE_HEADER_IDS`]: Every id kramdown accepts, any XML name like
132//!   `{#a.b}` or `{#_x}`. Instead, those are left as text.
133//! - ☐ [`ENABLE_HEADER_IDS`]: An id before an atx header's closing hashes,
134//!   `# A {#a} ##`, left as text. Instead, it's the header's id.
135//! - ⊟ [`ENABLE_LIST_ITEM_PARAGRAPHS`]: Tight and loose list items decided
136//!   per item, not per list: an item's first paragraph isn't wrapped in a
137//!   paragraph unless a blank line follows it.
138//! - ☐ [`ENABLE_LIST_ITEM_PARAGRAPHS`]: An end-of-block marker after a
139//!   list wrapping its last item in a paragraph. Instead, the item stays
140//!   tight.
141//! - ⊟ [`ENABLE_TASK_LISTS`]: Task list items, `* [x] done`, from
142//!   kramdown's GFM parser.
143//! - ☐ [`ENABLE_TASK_LISTS`]: Task items as kramdown's GFM parser reads
144//!   them: an empty `[ ]` is text, and `* {:.c} [x] a` is a task. Instead,
145//!   the empty box is a task, and the box after an attribute list is text.
146//! - ⊟ [`ENABLE_DEFINITION_LISTS`]: Definition lists, one term per line. A
147//!   definition's first paragraph isn't wrapped in a paragraph unless a
148//!   blank line comes before it. At most one blank line may separate the
149//!   terms from their first definition, any number may separate
150//!   definitions, and a definition with an empty first line is indented by
151//!   four spaces.
152//! - ☐ [`ENABLE_DEFINITION_LISTS`]: Separate terms on lines joined by one
153//!   span, like `*a\nb*`. Instead, they form a single term.
154//! - ☐ [`ENABLE_DEFINITION_LISTS`]: A definition's first line with its
155//!   leading whitespace stripped, so `:     text` is a paragraph. Instead,
156//!   four or more spaces make it code.
157//! - ☐ [`ENABLE_DEFINITION_LISTS`]: A space or tab required after the
158//!   `:`. Instead, `term\n:text` is a definition list.
159//! - ⊟ [`ENABLE_TABLES`]: Tables with a header row.
160//! - ☐ [`ENABLE_TABLES`]: Several header rows above the separator line.
161//!   Instead, the rows before the last make a paragraph.
162//! - ☐ [`ENABLE_TABLES`]: Rows wider than the header, widening the table.
163//!   Instead, the extra cells are dropped.
164//! - ☐ [`ENABLE_TABLES`]: A table with a header followed by a line that
165//!   isn't a row, which makes it all a paragraph. Instead, it's a table,
166//!   with the line as another row.
167//! - ☐ [`ENABLE_TABLES`]: A header and separator line with no rows after
168//!   them read as a paragraph. Instead, they're a table.
169//! - ☐ [`ENABLE_TABLES`]: Separator lines in a table body, and footer
170//!   separator lines, `|===`. Instead, each is a row of dashes or equals
171//!   signs after a header row. Without one, `|===` is a header's separator
172//!   line, and a table with a separator after its first rows is a
173//!   paragraph.
174//! - ☐ [`ENABLE_TABLES`]: Two or more lines of only table separators,
175//!   which kramdown doesn't treat as a table. Instead, they're parsed as
176//!   one.
177//! - ☑ [`ENABLE_TABLES_WITHOUT_HEADERS`]: A separator line with fewer
178//!   cells than the header, or `+` between its cells.
179//! - ⊟ [`ENABLE_TABLES_WITHOUT_HEADERS`]: Tables without a header row.
180//! - ⊟ [`ENABLE_TABLES_WITHOUT_HEADERS`]: A `|` in a code span in a table
181//!   cell, kept in that cell.
182//! - ☐ [`ENABLE_TABLES_WITHOUT_HEADERS`]: A row starting with `|` after one
183//!   that doesn't, given an empty first cell. Instead, its cells don't
184//!   shift.
185//! - ☐ [`ENABLE_TABLES_WITHOUT_HEADERS`]: Tables without a header row in
186//!   blockquotes, list items and footnotes. Instead, they're text, with an
187//!   empty table before them.
188//! - ☐ [`ENABLE_TABLES_WITHOUT_HEADERS`]: A `\|` in a code span in a table
189//!   cell keeping its backslash. Instead, it's dropped.
190//! - ☐ [`ENABLE_TABLES_WITHOUT_HEADERS`]: A `|` in HTML `<code>` in a cell
191//!   kept in that cell. Instead, it starts another cell.
192//! - ☐ [`ENABLE_TABLES_WITHOUT_HEADERS`]: A code span over two lines of a
193//!   table, which makes them a paragraph. Instead, they're a table.
194//! - ☐ [`ENABLE_TABLES_WITHOUT_HEADERS`]: A line with a `|` only inside
195//!   inline math read as a table row. Instead, it's a paragraph.
196//! - ⊟ [`ENABLE_MATH`]: Math blocks, `$$…$$` alone in a paragraph.
197//! - ☐ [`ENABLE_MATH`]: Blank lines in a math block. Instead, a blank line
198//!   splits it into paragraphs.
199//! - ☐ [`ENABLE_MATH`]: Math blocks only between block boundaries, so `$$`
200//!   right after or right before a fence or header is inline math in a
201//!   paragraph. Instead, it's a math block.
202//! - ☐ [`ENABLE_MATH`]: `$$…$$` alone in a list item or definition read
203//!   as a math block. Instead, it's inline math.
204//! - ⊟ [`ENABLE_HTML_BLOCK_ENDS`]: HTML blocks, with Markdown inside them
205//!   left as HTML. A block ends at the end tag of the element that opened
206//!   it, and text after that is parsed as Markdown, as long as no blank line
207//!   comes before the end tag.
208//! - ☐ [`ENABLE_HTML_BLOCK_ENDS`]: Blank lines inside an HTML block.
209//!   Instead, as in CommonMark, a blank line ends the block, and what
210//!   follows is parsed as Markdown.
211//! - ☐ [`ENABLE_HTML_BLOCK_ENDS`]: Every element that isn't span-level,
212//!   like `<details>` or a custom tag, ending at its end tag. Instead, an
213//!   element outside a fixed list runs to the next blank line.
214//! - ☐ [`ENABLE_HTML_BLOCK_ENDS`]: An end tag inside a comment or an
215//!   attribute value leaving the block open. Instead, it ends the block
216//!   early.
217//! - ☐ [`ENABLE_HTML_BLOCK_ENDS`]: HTML blocks in a blockquote ending at
218//!   their end tag. Instead, they run to the next blank line.
219//! - ⊟ [`ENABLE_MARKDOWN_ATTRIBUTE`]: `markdown="1"` on a block element.
220//!   Its content is parsed as Markdown and the attribute is removed.
221//! - ☐ [`ENABLE_MARKDOWN_ATTRIBUTE`]: `markdown="1"` on elements whose
222//!   content kramdown reads as spans, like `<p>` and `<h1>`. Instead, their
223//!   content is left as HTML.
224//! - ☐ [`ENABLE_MARKDOWN_ATTRIBUTE`]: `markdown="1"` with text on the start
225//!   tag's line, or after the end tag. Instead, that text is left as HTML.
226//! - ☐ [`ENABLE_MARKDOWN_ATTRIBUTE`]: `markdown='1'`, in single quotes.
227//!   Instead, it's ignored.
228//! - ☐ [`ENABLE_MARKDOWN_ATTRIBUTE`]: `markdown="block"`,
229//!   `markdown="span"` and `markdown="0"`. Instead, the attribute is kept,
230//!   and the content is left as HTML in a block element and parsed as
231//!   Markdown in a span.
232//! - ⊟ [`ENABLE_SPAN_TAG_PARAGRAPHS`]: A line with only a span-level tag,
233//!   like `<img>`, starting a paragraph together with the text on the next
234//!   line.
235//! - ☐ [`ENABLE_SPAN_TAG_PARAGRAPHS`]: A line with only a span-level tag,
236//!   followed by a blank line, as a paragraph of its own. Instead, it's an
237//!   HTML block.
238//! - ☐ [`ENABLE_SPAN_TAG_PARAGRAPHS`]: Lines in `<pre>` left as written.
239//!   Instead, a line with only a span-level tag is joined to the next there
240//!   too.

242//! ## Text markup
243//!
244//! - ⊟ Automatic links, `<http://example.com>` and `<me@example.com>`.
245//! - ☐ `<mailto:me@example.com>` with only the address as the link text.
246//!   Instead, the link text includes `mailto:`.
247//! - ☐ Automatic links with a space in the URL, or a non-ASCII email
248//!   address. Instead, they're text.
249//! - ⊟ Inline links, with single- or double-quoted titles.
250//! - ☐ Inline link titles as kramdown reads them: an empty title leaves
251//!   the whole link as text, and a title in parentheses is part of the URL.
252//!   Instead, the first is a link without a title, and the second a title.
253//! - ☐ Spaces in an inline link's URL, `[a](b c.html)`. Instead, it's
254//!   parsed as text.
255//! - ☐ A link inside link text, `[a [b](v) c](u)`, left as text in the
256//!   outer link. Instead, the inner one is the link.
257//! - ⊟ Reference links, `[text][id]`, `[text][]` and `[text]`, matched
258//!   case-insensitively.
259//! - ☐ Spaces or a line break between a reference link's brackets,
260//!   `[text]\n[id]`. Instead, each pair of brackets is read on its own.
261//! - ☐ Brackets in a reference link's text, `[[1]][1]`. Instead, the inner
262//!   brackets form the link and the outer ones are text.
263//! - ⊟ Link definitions, and `\:` to keep one as text.
264//! - ☐ The last link definition of a name winning. Instead, the first
265//!   wins.
266//! - ☐ Link definitions with a space in the URL, `[a]: b c`, or a title in
267//!   parentheses, which kramdown takes as part of the URL. Instead, the
268//!   first is text and the second a title.
269//! - ⊟ Images, inline and by reference.
270//! - ☐ An image's alt text as written, including markup and straight
271//!   quotes, with only backslash escapes applied. Instead, its markup is
272//!   parsed and its dashes, ellipses and quotes made typographic.
273//! - ⊟ Emphasis and strong emphasis. `*` works inside words, `_` doesn't.
274//! - ☐ Emphasis delimiter runs kramdown reads differently, like `a*"b"*c`
275//!   or `This is **a *star*.` Instead, they're read by CommonMark's rules.
276//! - ☐ Empty emphasis, `****`, written as `<em>**</em>`. Instead, it's
277//!   text.
278//! - ☐ Emphasis inside the same kind of emphasis, `*a _b_ c*` or `_*b*_`,
279//!   left literal. Instead, it nests.
280//! - ☐ `***a***` and `___a___` as strong emphasis around emphasis.
281//!   Instead, they're emphasis around strong emphasis.
282//! - ⊟ Code spans.
283//! - ☐ A backtick next to a space kept literal, as in `` ` a ` ``.
284//!   Instead, it opens a code span.
285//! - ⊟ HTML spans, with Markdown parsed inside them.
286//! - ☐ The HTML spans kramdown leaves raw beyond its documented ones, like
287//!   `<u>`, `<mark>` and custom elements. Instead, Markdown is parsed in
288//!   them.
289//! - ☐ Unclosed HTML spans closed, and stray end tags and block tags in a
290//!   paragraph made text. Instead, they're kept as HTML.
291//! - ☐ The `parse_span_html` option. Instead, HTML spans are read as with
292//!   it on, kramdown's default.
293//! - ☐ Guillemets from `<<` and `>>`. Instead, they're parsed as text or
294//!   as an HTML tag.
295//! - ☑ [`ENABLE_ABBREVIATIONS`]: Abbreviations, `*[HTML]: …`. Each use
296//!   becomes an `<abbr>` in HTML events, with the attributes of any
297//!   attribute lists on the lines around the definition.
298//! - ⊟ [`ENABLE_FOOTNOTES`]: Footnotes, with block content in their
299//!   definitions.
300//! - ☐ [`ENABLE_FOOTNOTES`]: The last footnote definition of a name
301//!   winning, and a lazy line ending a definition. Instead, the first wins,
302//!   and lazy lines continue it.
303//! - ☐ [`ENABLE_FOOTNOTES`]: A footnote definition on a paragraph's next
304//!   line kept as text. Instead, it's a footnote.
305//! - ☐ [`ENABLE_FOOTNOTES`]: A table or math block indented in a footnote
306//!   definition. Instead, it's text.
307//! - ⊟ [`ENABLE_TYPOGRAPHY`]: Dashes, ellipses and smart quotes.
308//! - ☐ [`ENABLE_TYPOGRAPHY`]: Smart quotes where kramdown curls them the
309//!   other way, like `'Tis` and `5'10"`. Instead, they're curled as
310//!   pulldown-cmark curls them.
311//! - ☐ [`ENABLE_TYPOGRAPHY`]: Runs of four or more dashes made into dashes
312//!   as kramdown makes them. Instead, they're en dashes.
313//! - ⊟ [`ENABLE_MATH`]: Inline math, `$$…$$` in a paragraph with other
314//!   content. `$…$` stays text.
315//! - ☐ [`ENABLE_MATH`]: `\$$…$$` to make math alone in a paragraph inline.
316//!   Instead, it's left literal.
317//! - ⊟ [`ENABLE_STRIKETHROUGH`]: Strikethrough, `~~…~~`, from kramdown's
318//!   GFM parser. `~…~` stays text.
319//! - ☐ [`ENABLE_STRIKETHROUGH`]: Runs of tildes kramdown's GFM parser reads
320//!   differently, like `~~a~~~`, and `~~~a~~~` as a paragraph. Instead, the
321//!   first is text and the second a fence.
322//! - ⊟ [`ENABLE_RAW_HTML_SPANS`]: The HTML spans kramdown leaves raw, like
323//!   `<kbd>` and `<code>`, their text passed through unchanged.
324//! - ☐ [`ENABLE_RAW_HTML_SPANS`]: A nested tag of the same name in a raw
325//!   HTML span, like `<kbd>a <kbd>b</kbd> c</kbd>`. Instead, the first end
326//!   tag ends the raw text.
327//!
328//! ## Non-content elements
329//!
330//! - ☑ Tags for extensions kramdown doesn't have, like `{::something}`,
331//!   left as text.
332//! - ☐ Definition attribute lists, `: {:.cls} definition`. Instead,
333//!   they're parsed as text.
334//! - ☐ Term attribute lists, `{:#id} term`. Instead, they're parsed as
335//!   text.
336//! - ☐ Attribute list definitions, `{:name: .class}`, and references to
337//!   them, including kramdown's `standalone`, `footnotes` and `auto_ids`.
338//!   Instead, definitions are removed and references ignored.
339//! - ☐ The `options` extension. Instead, its block form is removed, with
340//!   any body kept as Markdown, and its span form is left as text.
341//! - ⊟ [`ENABLE_END_OF_BLOCK_MARKERS`]: The end-of-block marker `^`,
342//!   closing the paragraph, list, blockquote or code block before it.
343//! - ☐ [`ENABLE_END_OF_BLOCK_MARKERS`]: An indented `^` kept as text.
344//!   Instead, it's a marker.
345//! - ☐ [`ENABLE_END_OF_BLOCK_MARKERS`]: A marker after an HTML block.
346//!   Instead, it's text.
347//! - ⊟ [`ENABLE_BLOCK_ATTRIBUTES`]: Block attribute lists, on the line
348//!   before or after a block, or alone between blocks to apply to the next
349//!   one.
350//! - ⊟ [`ENABLE_BLOCK_ATTRIBUTES`]: Block attribute lists on link
351//!   definitions, applied to the links and images that use them.
352//! - ☐ [`ENABLE_BLOCK_ATTRIBUTES`]: A block attribute list after a list
353//!   item ending the list. Instead, it's applied to the list, but the items
354//!   after it stay in the same list.
355//! - ☐ [`ENABLE_BLOCK_ATTRIBUTES`]: Block attribute lists on HTML blocks.
356//!   Instead, one before the block is dropped, and one after goes to the
357//!   next block.
358//! - ☐ [`ENABLE_BLOCK_ATTRIBUTES`]: An attribute list indented by four
359//!   spaces kept as text. Instead, it's read.
360//! - ☐ [`ENABLE_BLOCK_ATTRIBUTES`]: An attribute list's attribute replacing
361//!   the element's own of the same name, like an ordered list's `start`.
362//!   Instead, both are written.
363//! - ⊟ [`ENABLE_SPAN_ATTRIBUTES`]: Span attribute lists, directly after
364//!   emphasis, a link, an image or a code span.
365//! - ⊟ [`ENABLE_SPAN_ATTRIBUTES`]: The empty span attribute list, `{::}`,
366//!   as a separator between spans.
367//! - ☐ [`ENABLE_SPAN_ATTRIBUTES`]: Span attribute lists after a collapsed
368//!   reference link, `[a][]{:.c}`. Instead, they're text.
369//! - ☐ [`ENABLE_SPAN_ATTRIBUTES`]: Span attribute lists after HTML spans
370//!   and inline math. Instead, they're text.
371//! - ☐ [`ENABLE_SPAN_ATTRIBUTES`]: `{::}` on a line of its own kept as
372//!   text. Instead, it's dropped.
373//! - ⊟ [`ENABLE_ITEM_ATTRIBUTES`]: List item attribute lists,
374//!   `* {:.cls} item`.
375//! - ☐ [`ENABLE_ITEM_ATTRIBUTES`]: Only the first of two item attribute
376//!   lists read, `* {:.a}{:.b} item`. Instead, both are.
377//! - ⊟ [`ENABLE_COMMENTS`]: The `comment` extension, as a block or span,
378//!   emitted as an HTML comment.
379//! - ☐ [`ENABLE_COMMENTS`]: The `comment` extension in a blockquote.
380//!   Instead, it's text.
381//! - ⊟ [`ENABLE_NOMARKDOWN`]: The `nomarkdown` extension, as a block or
382//!   span, emitted as raw HTML unless its `type` names another converter.
383//! - ☐ [`ENABLE_NOMARKDOWN`]: The `nomarkdown` extension in a blockquote.
384//!   Instead, it's text.
385//!
386//! ## Converter
387//!
388//! Not part of the syntax, but features Jekyll sites rely on.
389//!
390//! - ☐ The `toc_levels` option. Instead, every heading level is listed.
391//! - ⊟ [`ENABLE_AUTO_IDS`]: Automatic header ids, generated from the
392//!   heading's text without markup, the same way as kramdown's GFM parser,
393//!   Jekyll's default.
394//! - ☐ [`ENABLE_AUTO_IDS`]: Ids for headings with images or raw HTML
395//!   spans, made from the spans' text and not an image's alt text. Instead,
396//!   they're made from the alt text and not the spans' text.
397//! - ⊟ [`ENABLE_TABLES_OF_CONTENTS`]: `{:toc}` tables of contents, nested
398//!   by heading level. Headings with the class `no_toc` are excluded, and
399//!   links inside headings are left out. If there are no headings, the
400//!   marked list is removed.
401//! - ☐ [`ENABLE_TABLES_OF_CONTENTS`]: Only the first list marked `{:toc}`
402//!   made a table of contents. Instead, every one is.
403//! - ☐ [`ENABLE_TABLES_OF_CONTENTS`]: kramdown's ids on a table of
404//!   contents, `markdown-toc` on the list and `markdown-toc-…` on its links.
405//!   Instead, there are none.
406//!
407//! # How it works
408//!
409//! Reading a document takes four steps.
410//!
411//! 1. The Markdown is rewritten wherever kramdown reads a line differently
412//!    from CommonMark, so that pulldown-cmark reads it kramdown's way. For
413//!    example, a blank line goes in after the end tag of an HTML block,
414//!    since kramdown ends the block there and CommonMark doesn't. Syntax
415//!    pulldown-cmark can't read at all, like `{::comment}` or the
416//!    end-of-block marker, is replaced with a stand-in: a little HTML that
417//!    pulldown-cmark reads as a block or a span, and that the reader later
418//!    swaps for what it stands for.
419//! 2. pulldown-cmark parses the rewritten text.
420//! 3. A reader takes the events a block at a time. It takes attribute
421//!    lists out of the text and attaches them to the elements they belong
422//!    to, puts back what the stand-ins stand for, and corrects the events
423//!    where kramdown's structure differs, like in definition lists, list
424//!    item paragraphs, header ids and abbreviations.
425//! 4. With tables of contents on, all of the events are read first, and
426//!    each list marked `{:toc}` is replaced with links to the headings.
427//!
428//! The ranges from [`Events::into_offset_iter`] are mapped back through the
429//! rewrites, so they point into the Markdown as it was given.
430//!

432//! [`ENABLE_AUTO_IDS`]: Extensions::ENABLE_AUTO_IDS

486/// A kramdown document, ready to parse.
487///
488/// [`Document::new`] rewrites the source once. Each call to
489/// [`Document::events`] parses that from the start, so the document can be
490/// read more than once without redoing the rewriting.
491///
492/// The events borrow the document, so it has to outlive them.
493///
494/// ```
495/// use pulldown_kram::{Document, Extensions, html, pulldown_cmark::{Event, Tag}};
496///
497/// let document = Document::new("# Intro\n\n## Usage\n", Extensions::all());
498///
499/// // Collect the heading ids...
500/// let ids: Vec<String> = document
501///     .events()
502///     .filter_map(|(event, _)| match event {
503///         Event::Start(Tag::Heading { id, .. }) => id.map(|id| id.to_string()),
504///         _ => None,
505///     })
506///     .collect();
507/// assert_eq!(ids, ["intro", "usage"]);
508///
509/// // ...then parse it again to render it.
510/// let mut out = String::new();
511/// html::push_html(&mut out, document.events());
512/// assert_eq!(out, "<h1 id=\"intro\">Intro</h1>\n<h2 id=\"usage\">Usage</h2>\n");
513/// ```
514#[derive(Debug, Clone)]
515pub struct Document<'a> {
516    text: Cow<'a, str>,
517    /// Where the rewritten text was in the markdown.
518    offsets: Offsets,
519    /// Where the stand-ins are in the text, and what each stands for.
520    marks: Vec<Mark<'a>>,
521    abbreviations: Vec<Abbreviation<'a>>,
522    options: Options,
523}
524
525impl<'a> Document<'a> {
526    /// Prepares `markdown` for parsing with `options`, which can be full
527    /// [`Options`] or just [`Extensions`].
528    ///
529    /// Only the enabled extensions are read. Without one, its syntax is read
530    /// as CommonMark would.
531    ///
532    /// pulldown-cmark reads some of kramdown's syntax differently, so the
533    /// source is rewritten first for it to read kramdown's way. Most
534    /// rewrites are small: kramdown ends an HTML block at its end tag, for
535    /// example, so a blank line is added there for CommonMark to end it too.
536    /// Syntax CommonMark has no way to read at all, like an end-of-block
537    /// marker, is replaced by a stand-in, and [`Document::events`] gives out
538    /// what it stands for instead.
539    ///
540    /// None of this shows in the events: no stand-in is given out, and the
541    /// ranges from [`Events::into_offset_iter`] point into `markdown`, not the
542    /// rewritten text. Markdown that needs no rewriting is borrowed, not
543    /// copied.
544    ///
545    /// ```
546    /// use pulldown_kram::{Document, Extensions, html};
547    ///
548    /// let render = |extensions| {
549    ///     let document = Document::new("*a*{:.x}\n", extensions);
550    ///     let mut out = String::new();
551    ///     html::push_html(&mut out, document.events());
552    ///     out
553    /// };
554    /// assert_eq!(render(Extensions::all()), "<p><em class=\"x\">a</em></p>\n");
555    ///
556    /// // Without span attribute lists, `{:.x}` is text.
557    /// let extensions = Extensions::all().difference(Extensions::ENABLE_SPAN_ATTRIBUTES);
558    /// assert_eq!(render(extensions), "<p><em>a</em>{:.x}</p>\n");
559    /// ```
560    pub fn new(markdown: &'a str, options: impl Into<Options>) -> Self {
561        let options = options.into();
562        // The stand-ins go in first, as what they stand for borrows from
563        // `markdown`, not from a rewrite of it.
564        let Marked {
565            mut text,
566            mut offsets,
567            mut marks,
568            abbreviations,
569        } = StandIns::rewrite(markdown, options.kramdown);
570        for (extension, rewrite) in REWRITES {
571            if !options.kramdown.contains(extension) {
572                continue;
573            }
574            let (Cow::Owned(rewritten), edits) = rewrite(&text) else {
575                continue;
576            };
577            for mark in &mut marks {
578                mark.at = edits.moved(mark.at);
579            }
580            offsets = offsets.then(edits);
581            text = Cow::Owned(rewritten);
582        }
583        Self {
584            text,
585            offsets,
586            marks,
587            abbreviations,
588            options,
589        }
590    }
591
592    /// Returns the document's events, each with its attributes.
593    ///
594    /// Events are returned a block at a time, as each block is finished,
595    /// since an attribute list after a block still applies to it. With
596    /// [`Extensions::ENABLE_TABLES_OF_CONTENTS`], every event is collected
597    /// before the first is returned instead, so tables of contents can link
598    /// to headings that come after them. [`Extensions::streamable()`] turns
599    /// on everything else.
600    ///
601    /// [`Events::into_offset_iter`] also yields each event's byte range in
602    /// the markdown.
603    ///
604    /// ```
605    /// use pulldown_kram::{Document, Extensions, pulldown_cmark::{Event, Tag}};
606    ///
607    /// // The attribute list on the line after the paragraph applies to it.
608    /// let document = Document::new("A paragraph.\n{: .note}\n", Extensions::all());
609    /// let (_, attributes) = document
610    ///     .events()
611    ///     .find(|(event, _)| matches!(event, Event::Start(Tag::Paragraph)))
612    ///     .unwrap();
613    /// assert!(attributes.has_class("note"));
614    /// ```
615    pub fn events(&self) -> Events<'_> {
616        let reader = read::Reader::new(&self.text, self.options, &self.marks)
617            .abbreviating(&self.abbreviations);
618        let items = if self
619            .options
620            .kramdown
621            .contains(Extensions::ENABLE_TABLES_OF_CONTENTS)
622        {
623            Items::Read(toc::Toc::replace_lists(reader.collect()).into_iter())
624        } else {
625            Items::Streamed(Box::new(reader))
626        };
627        Events {
628            items,
629            offsets: &self.offsets,
630        }
631    }
632}
633
634/// An iterator over the events of a [`Document`] and their attributes,
635/// returned by [`Document::events`].
636///
637/// Each item pairs a [`pulldown_cmark::Event`] with its [`Attributes`]. The
638/// event is pulldown-cmark's own type, not a wrapper, so dropping the
639/// attributes leaves events that anything built for pulldown-cmark accepts.
640///
641/// ```
642/// use pulldown_kram::{Document, Extensions, pulldown_cmark::Event};
643///
644/// let document = Document::new("*a*{:.x}\n", Extensions::all());
645/// let events: Vec<Event> = document.events().map(|(event, _)| event).collect();
646/// assert_eq!(events.len(), 5);
647/// ```
648///
649/// The attributes say what kramdown's attribute lists assigned to each
650/// event:
651///
652/// ```
653/// use pulldown_kram::{Document, Extensions, pulldown_cmark::Event};
654///
655/// let document = Document::new("*a*{:.x}\n", Extensions::all());
656/// let classes: Vec<_> = document
657///     .events()
658///     .filter_map(|(event, attributes)| match event {
659///         Event::Start(_) => Some(attributes.classes),
660///         _ => None,
661///     })
662///     .collect();
663/// assert_eq!(classes, [vec![], vec!["x".into()]]);
664/// ```
665pub struct Events<'a> {
666    items: Items<'a>,
667    /// Where the items' ranges were in the document's markdown.
668    offsets: &'a Offsets,
669}
670
671/// Where the events come from.
672enum Items<'a> {
673    /// Read as they're asked for.
674    Streamed(Box<read::Reader<'a>>),
675    /// Read all at once.
676    Read(std::vec::IntoIter<read::Item<'a>>),
677}
678
679impl<'a> Events<'a> {
680    /// Converts this into an iterator that also yields each event's byte
681    /// range in the document's markdown, like pulldown-cmark's
682    /// [`Parser::into_offset_iter`](pulldown_cmark::Parser::into_offset_iter).
683    pub fn into_offset_iter(self) -> OffsetIter<'a> {
684        OffsetIter(self)
685    }
686
687    /// The next item, with its range in the rewritten text.
688    fn item(&mut self) -> Option<read::Item<'a>> {
689        match &mut self.items {
690            Items::Streamed(reader) => reader.next(),
691            Items::Read(items) => items.next(),
692        }
693    }
694}
695
696impl<'a> Iterator for Events<'a> {
697    type Item = (Event<'a>, Attributes<'a>);
698
699    fn next(&mut self) -> Option<Self::Item> {
700        self.item()
701            .map(|item| (item.event, item.attribute_lists.attributes))
702    }
703
704    fn size_hint(&self) -> (usize, Option<usize>) {
705        match &self.items {
706            Items::Streamed(reader) => reader.size_hint(),
707            Items::Read(items) => items.size_hint(),
708        }
709    }
710}
711
712impl FusedIterator for Events<'_> {}
713
714impl fmt::Debug for Events<'_> {
715    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
716        let mut events = f.debug_struct("Events");
717        match &self.items {
718            Items::Streamed(reader) => events
719                .field("streamed", &true)
720                .field("ready", &reader.size_hint().0),
721            Items::Read(items) => events
722                .field("streamed", &false)
723                .field("ready", &items.len()),
724        };
725        events.finish()
726    }
727}

729/// An iterator over the events of a [`Document`], with their attributes and
730/// byte ranges in the markdown the document was created from.
731///
732/// Before parsing, the markdown may be rewritten slightly so pulldown-cmark
733/// parses it the way kramdown does. Ranges still point into the original
734/// text: a range that overlaps a rewritten part covers all of it, and a
735/// range inside an inserted line is empty, at the point where the line was
736/// inserted. Every range has `start <= end`, falls on char boundaries, and
737/// lies within the markdown.
738///
739/// ```
740/// use pulldown_kram::{Document, Extensions, pulldown_cmark::{Event, Tag}};
741///
742/// let markdown = "<div markdown=\"1\">\n*a*{:.x} b\n</div>\n";
743/// let document = Document::new(markdown, Extensions::all());
744/// let (_, attributes, range) = document
745///     .events()
746///     .into_offset_iter()
747///     .find(|(event, _, _)| matches!(event, Event::Start(Tag::Emphasis)))
748///     .unwrap();
749/// assert_eq!(&markdown[range], "*a*");
750/// assert!(attributes.has_class("x"));
751/// ```
752pub struct OffsetIter<'a>(Events<'a>);
753
754impl<'a> Iterator for OffsetIter<'a> {
755    type Item = (Event<'a>, Attributes<'a>, Range<usize>);
756
757    fn next(&mut self) -> Option<Self::Item> {
758        let item = self.0.item()?;
759        let range = self.0.offsets.original(item.range);
760        Some((item.event, item.attribute_lists.attributes, range))
761    }
762
763    fn size_hint(&self) -> (usize, Option<usize>) {
764        self.0.size_hint()
765    }
766}
767
768impl FusedIterator for OffsetIter<'_> {}
769
770impl fmt::Debug for OffsetIter<'_> {
771    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
772        f.debug_struct("OffsetIter")
773            .field("events", &self.0)
774            .field("rewritten", &!self.0.offsets.is_empty())
775            .finish()
776    }
777}

809    #[test]
810    fn events_into_offset_iter_offsets_are_into_the_markdown() {
811        let documents = [
812            // Nothing rewritten.
813            "# Héading {#h}\n\nSome *tëxt*{:.x} and `code`.\n\n* one\n* two\n{:.list}\n\n> quote\n",
814            // Blank lines added inside an element.
815            "<div markdown=\"1\">\n# Inside\n\n*ä*{:.x} b\n</div>\nafter\n",
816            // A span tag's line joined to the next.
817            "<span class=\"g\">  \n*ä* b\n</span>\n\nafter ü\n",
818            // Both.
819            "<div markdown=\"1\">\n<img src=\"é\" />\nnaïve *text*\nand `code`\n</div>\n\nafter ü\n",
820        ];
821        let options = [Extensions::all(), Extensions::streamable()];
822        for markdown in documents {
823            for options in options {
824                let document = Document::new(markdown, options);
825                let mut checked = 0;
826                for (event, _, range) in document.events().into_offset_iter() {
827                    let Some(source) = markdown.get(range.clone()) else {
828                        panic!("{event:?} at {range:?} isn't in {markdown:?}");
829                    };
830                    let (Event::Text(text) | Event::Code(text) | Event::InlineHtml(text)) = &event
831                    else {
832                        continue;
833                    };
834                    if !document.offsets.touches(&range) {
835                        assert!(
836                            source.contains(text.as_ref()),
837                            "{event:?} at {range:?} is {source:?}"
838                        );
839                        checked += 1;
840                    }
841                }
842                assert!(checked >= 3, "only {checked} checked in {markdown:?}");
843                // The offsets don't change the events.
844                assert!(
845                    document
846                        .events()
847                        .into_offset_iter()
848                        .map(|(event, attributes, _)| (event, attributes))
849                        .eq(document.events())
850                );
851            }
852        }
853    }
