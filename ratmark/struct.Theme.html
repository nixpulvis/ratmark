Expand description

The styles used for each kind of Markdown element.

Inline styles like Theme::strong are patched over the style of the block they appear in, so a theme only needs to set what changes.

Fields§

§text: Style

Plain text, which everything else is patched over.

§headings: [Style; 6]

Heading text, by level from # to ######.

§heading_marker: Option<Style>

The style of # marks drawn in front of each heading, Markdown or HTML, to show its level. None, the default, draws no marks.

§emphasis: Style

*Emphasis*.

§strong: Style

**Strong** text.

§strikethrough: Style

~~Struck through~~ text.

§link: Style

Link text.

§image: Style

An image’s [image: alt] label, patched over the link style.

§code: Style

Inline code.

§code_block: Style

Fenced and indented code. The background fills the block’s width.

§code_block_padding: bool

Leave a column on either side of each code block, where ‹ and › show code cut off at the edges. Without it the code takes the full width, and the marks are drawn over its first and last columns.

§quote: Style

Text in a block quote.

§quote_marker: Style

The bar down the side of a block quote.

§list_marker: Style

List bullets and numbers, and task list boxes.

§rule: Style

A horizontal rule.

§math: Style

Inline and display math, shown as written.

§footnote: Style

Footnote references and labels, like [1].

§table_border: Style

The lines between a table’s columns and rows.

§table_header: Style

A table’s header row.

§table_row_rules: bool

Draw a rule between body rows too, not just under the header.

§small: Style

Text from <small> tags, used for things like dates under a title.

§syntax: Option<&'static str>

The syntect theme used to color code blocks, when the syntax feature is on. Only its foreground colors are used. Besides syntect’s bundled themes there’s "ansi", which colors code with terminal color numbers, like Theme::ansi_dark.

As in bat, a syntect color with an alpha of 00 names a terminal color by the number in its red, and an alpha of 01 keeps the code block’s own foreground.

§classes: Vec<(String, Style)>

Styles for elements with these classes, written like CSS class selectors, .note or .note.warning, and patched in order over everything inside a matching element. A code block inside takes its background. Classes come from HTML, with the html feature, and from a kramdown attribute list right after inline code, like `x`{:.new}, with the kramdown feature.

Source

pub fn ansi_dark() -> Self

Colors picked from the terminal’s palette, for a dark background.

Each color is a terminal color number, like 4 for blue, never a fixed RGB value, so the terminal’s palette decides what it looks like. Text and the background keep the terminal’s defaults. Code, inline or in blocks, sits on gray 234 from the 256-color ramp, which suits a dark background.

Source

pub fn ansi_light() -> Self

Colors picked from the terminal’s palette, for a light background. The same as Theme::ansi_dark, but code sits on the light gray 255.

Source

pub fn plain() -> Self

No colors at all, only bold, italic, underline, dim and reversed text. It reads the same on any background, and in terminals without color.
