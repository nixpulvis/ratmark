Render Markdown as a Ratatui StatefulWidget, or into Ratatui text.

Draw a MarkdownView in any Ratatui Terminal, then drive its state from input:

use ratmark::{MarkdownState, MarkdownView, Theme};

let theme = Theme::default();
let mut state = MarkdownState::new("# Hello\n\nRead [the docs](https://docs.rs/ratmark).");

// `terminal` is your app's `ratatui_core::terminal::Terminal`, like
// `Terminal::new(CrosstermBackend::new(io::stdout()))?` from ratatui-crossterm.
terminal.draw(|frame| {
    let view = MarkdownView::new(&theme);
    frame.render_stateful_widget(view, frame.area(), &mut state);
})?;

// On input, scroll, focus the next link, or find the link under a click.
state.scroll_by(1);
state.focus_next();
let focused = state.focused().map(|link| link.url.as_str()); // Some("https://docs.rs/ratmark")
let clicked = state.link_at(5, 2).map(|link| link.url.as_str()); // Some("https://docs.rs/ratmark")

MarkdownState holds the document, its layout and where you are in it. MarkdownView wraps the document to the width it’s given, rewrapping when the width changes, and draws it scrolled with the focused link highlighted.

Underneath, Rendered::render lays a document out for a given width and returns its lines along with where each link landed.

use ratmark::{Rendered, Theme};

let theme = Theme::default();
let markdown = "# Hi\n\nSee [the docs](https://docs.rs).";
let rendered = Rendered::render(markdown, 40, &theme);

assert_eq!(rendered.lines[0].to_string(), "Hi");
assert_eq!(rendered.lines[0].spans[0].style, theme.headings[0]);
assert_eq!(rendered.links[0].url, "https://docs.rs");

A Theme holds every style. Theme::ansi_dark is the default, and Theme::ansi_light suits a light background. Both use terminal color numbers, so the terminal’s palette decides what they look like. Theme::plain uses no colors at all. Every style is a public field, so making your own is a struct literal.

CommonMark plus tables, footnotes, strikethrough, task lists, definition lists and math are supported. Code too wide for the page scrolls sideways rather than wrapping.

§Features

  • The links feature draws real links, which the terminal or browser can open, on backends that support them. MarkdownState::with_link_base makes relative links absolute.
  • The syntax feature highlights code blocks with syntect.
  • The html feature reads HTML embedded in the Markdown for its text, links and simple formatting.
    • <a href> is a link.
    • <strong> and <b> are strong.
    • <em>, <i> and <cite> are emphasized.
    • <code>, <kbd>, <samp> and <tt> are code.
    • <s>, <del> and <strike> are struck through.
    • <small>, <sub> and <sup> are small.
    • <h1> to <h6> are headings.
    • <pre> is a code block, <br> a line break and <hr> a rule.
    • <li> is a bulleted item, in <ul> or <ol>.
    • <img src alt> is an image, like Markdown’s, and <svg aria-label> a figure.
    • <p>, <div>, <blockquote>, <section>, <article>, <header>, <footer>, <figure>, <table>, <tr>, <dl>, <dt> and <dd> start a new line, and <td> and <th> are spaced apart.
    • Any element’s class is styled by Theme::classes.
    • Other tags show only their text. Comments, and the content of <script>, <style>, <template>, <head> and <svg>, are left out.
  • The kramdown feature reads Markdown written for kramdown, Jekyll’s default, with pulldown-kram, which lists how much of kramdown it understands.
    • A list followed by {:toc} is a table of contents, linking to each heading without the class no_toc.
    • Attribute lists, like {:.no_toc}, are taken out of the text, and classes on inline code, like `x`{:.new}, are styled by Theme::classes.
    • Markdown inside markdown="1" elements is rendered as Markdown.
    • A line of only a span tag, like <img>, starts a paragraph rather than an HTML block.
  • The front-matter-yaml and front-matter-toml features add front_matter, for splitting YAML or TOML front matter off the top of a document before rendering the rest, and deserializing it with serde.

Modules§

front_matter
A preamble of metadata at the very top of a file, fenced off from the document after it. Static site generators like Jekyll and Hugo read it from Markdown for a page’s title, date, tags and layout, and it isn’t meant to be shown as part of the page.

MarkdownState
A document and where it’s scrolled to, for MarkdownView. Scrolling stays inside the document as last drawn.
MarkdownView
Draws a MarkdownState’s document, laid out to fit the area it’s given, scrolled and with its focused link highlighted.
Overflow
A code block too wide for the page. Its lines are cut off at the page’s edge, with a › where there’s more, and can be drawn shifted sideways to show the rest.
Region
A stretch of one line, in columns from the start of the line.
Rendered
A rendered document.
Theme
