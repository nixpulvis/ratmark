Module gesture 

Source
Expand description

Scrolling with a wheel, a trackpad or a finger, a cell at a time.

Each gesture only goes one way, down the page, or sideways through the wide code block under the pointer, or where a finger first touched, so a swipe that’s a little diagonal doesn’t do both. Hosts that report movement in pixels, like a browser, move the page as far as the hand does, a line or a column at a time once one’s worth adds up, and a flick keeps the page gliding for a bit, slowing down, like a page in the browser does.

Gestures does the arithmetic, from pixels and timestamps, and hands each whole cell of movement to a callback as a Step, which Step::apply carries out on a MarkdownState. Each host feeds it its own events:

  • In a terminal, terminal::Wheel takes the wheel’s ticks, like crossterm’s MouseEventKind::ScrollDown.
  • In a browser, the web feature’s web::listen follows the wheel and touch events over the element a view is drawn in, like Ratzilla’s.
  • Anywhere else that reports movement in pixels, call Gestures’ methods from its events, and Gestures::glide once a frame after Gestures::touch_end says a touch was a flick.
use ratmark::MarkdownState;
use ratmark::gesture::Gestures;

let markdown = (1..=20).map(|n| format!("{n}\n\n")).collect::<String>();
let mut state = MarkdownState::new(markdown);
// Cells 8 pixels wide and 16 tall.
let mut gestures = Gestures::new(8.0, 16.0);

// Half a line doesn't move yet, the rest of a line and a half does.
gestures.wheel((0.0, 0.0), (0.0, 8.0), 0.0, |step| step.apply(&mut state));
assert_eq!(state.scroll(), 0);
gestures.wheel((0.0, 0.0), (0.0, 24.0), 10.0, |step| step.apply(&mut state));
assert_eq!(state.scroll(), 2);
