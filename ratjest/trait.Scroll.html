Expand description

Something a gesture scrolls, a Step at a time.

It’s a widget’s state, the part that keeps how far the widget is scrolled. Like when it’s drawn, it’s told the area the widget is in, which says whether the step is over it, and how much fits.

It’s implemented for Ratatui’s ListState and TableState, which scroll the way they do for the keys: by the selection when there is one, and by the offset when there isn’t. They don’t know how many rows they have, so a step can go past the last one, and the widget brings it back when it’s next drawn.

A widget of the app’s own implements it for its state, out of a Step::scroll for each way it goes. One that knows how much it has, like this, stops at its end. An app with several widgets is one too, which splits area as it does to draw, and tries each widget’s state in turn with the part it’s drawn in.

use ratatui::layout::Rect;
use ratjest::{Axis, Scroll, Step};

/// How far some lines of text are scrolled.
struct Lines {
    top: usize,
    len: usize,
}

impl Scroll for Lines {
    fn scroll(&mut self, step: Step, area: Rect) -> bool {
        let last = self.len.saturating_sub(usize::from(area.height));
        step.is_over(area) && step.scroll(Axis::Vertical, &mut self.top, last)
    }
}

let area = Rect::new(0, 0, 30, 5);
let mut lines = Lines { top: 0, len: 20 };

// A step from a wheel three lines down, over the lines.
let step = Step { axis: Axis::Vertical, cells: 3, column: 4, row: 2 };
assert!(lines.scroll(step, area));
assert_eq!(lines.top, 3);

fn scroll(&mut self, step: Step, area: Rect) -> bool

Carries out step on what’s drawn in area, and returns whether it moved. It doesn’t when the step isn’t over area, goes a way it doesn’t scroll, or it’s at the end.

impl Scroll for ListState

A list scrolls by its selection when it has one, since the list keeps the selected item in view, whatever its offset. With nothing selected it scrolls by its offset, the first item drawn.

area is where the items are drawn, inside the list’s block.

use ratatui::layout::Rect;
use ratatui::widgets::ListState;
use ratjest::{Axis, Scroll, Step};

let area = Rect::new(0, 0, 30, 5);
let mut state = ListState::default();

// A step from a wheel, three rows down, over the list.
let step = Step { axis: Axis::Vertical, cells: 3, column: 4, row: 2 };
assert!(state.scroll(step, area));
assert_eq!(state.offset(), 3);

// With an item selected, the selection moves.
state.select(Some(1));
assert!(state.scroll(step, area));
assert_eq!(state.selected(), Some(4));

The state doesn’t know how many items there are, so a step doesn’t stop at the last one. Like the state’s own scroll_down_by, it moves past, and the list brings it back to the last item when it’s next drawn. So a step at the end still says it moved, and the offset goes on until the last item is at the top. To stop where the last item is at the bottom, give Step::scroll the state’s offset_mut() and that end.

impl Scroll for TableState

A table scrolls like a list: by its selected row when it has one, and by its offset, the first row drawn, when it doesn’t. Nor does it know how many rows there are, so the table brings a step past the last one back when it’s next drawn.

area is where the rows are drawn, inside the table’s block and below its header.
