Scrolling a terminal UI with a wheel, a trackpad or a finger, a cell at a time.

Each gesture only goes one way, up and down, or sideways, so a swipe that’s a little diagonal doesn’t do both. Hosts that report movement in pixels, like a browser, move the view as far as the hand does, a line or a column at a time once one’s worth adds up, and a flick keeps the view gliding for a bit, slowing down, like a page in the browser does.

Gestures does the arithmetic, from pixels and timestamps, and hands each whole cell of movement to a callback as a Step. The callback moves whatever the app scrolls, and returns whether it moved, which ends the gesture at the end of what there is to scroll. Each host feeds it its own events:

  • In a terminal, terminal::Wheel takes the wheel’s ticks, like crossterm’s MouseEventKind::ScrollDown.
  • In a browser, the web feature’s web::listen follows the wheel and touch events over the element a view is drawn in, like Ratzilla’s.
  • Anywhere else that reports movement in pixels, call Gestures’ methods from its events, and Gestures::glide once a frame after Gestures::touch_end says a touch was a flick.

Nothing here draws, or depends on what does. A Step is only so many cells one way, over the cell the gesture is on.

use ratjest::{Axis, Gestures, Step};

// Twenty lines in a view five tall, so the top line is 0 through 15.
let mut top: isize = 0;
let mut scroll = |step: Step| {
    if step.axis != Axis::Vertical {
        return false;
    }
    let before = top;
    top = (top + step.cells).clamp(0, 15);
    top != before
};

// Cells 8 pixels wide and 16 tall.
let mut gestures = Gestures::new(8.0, 16.0);

// Half a line doesn't move yet, the rest of a line and a half does.
gestures.wheel((0.0, 0.0), (0.0, 8.0), 0.0, &mut scroll);
gestures.wheel((0.0, 0.0), (0.0, 24.0), 10.0, &mut scroll);
assert_eq!(top, 2);
